# 处理 OKWW 反作弊告警并暂停自动任务

本页适用于 `tools/okww_mcp.py` 连接本机安装版 OKWW 的路径。2026-11-15（UTC+08:00）收到用户关于“反作弊踢出提示，反复出现后曾有约 24 小时限制”的说明后，曾为当前工作区设置持久安全暂停。**这是避免继续提交自动任务的本地保护，不是解除处罚、规避检测或证明误判的功能。**

**当前状态（2026-11-16，UTC+08:00）：**用户明确回答已人工核查并要求通过启动器恢复自动日常。已保存[人工恢复授权](../runs/services/okww/manual-resume-20261116-0300.json)，将原暂停标记原样归档，未修改客户端检查逻辑。恢复依据是用户确认，不是独立验证无风险，也不是自动到期。官方启动器已在独立会话 2 通过原生按钮启动游戏；本次没有更新 OKWW。日常完成与否以对应运行结果为准。

## 区分已知事实和未知原因

| 证据 | 可以得出的结论 | 不能得出的结论 |
| --- | --- | --- |
| 用户报告弹窗明确提及反作弊踢出 | 应按反作弊告警处置，不再假设为普通网络故障 | 尚未独立读取弹窗、错误码或处罚记录，不能确认具体触发项 |
| 用户报告重复踢出后出现约 24 小时限制 | 应停止继续运行并保留证据 | “十几至二十次”或运行时长不是已核实的处罚阈值，不能据此制定安全次数或冷却时间 |
| 既有审查检查了部分输入、任务和恢复源码 | 已确认存在自动输入及通用弹窗处理 | 没有审计全部依赖、所有运行进程或服务器规则，不能证明整套运行环境必定符合游戏规则 |
| 本次离线回归通过 | 本地保护在所测分支拒绝提交任务 | 不能证明游戏不会再提示、账号不会被限制或封禁率下降 |

官方在 **2024-02-17** 发布的[《鳴潮》公平營運聲明](https://wutheringwaves.kurogames.com/zh-tw/main/news/detail/639)中，将宏脚本和自动挂机列入禁止范围，并提及按违规情况和次数处理。此页面在 2026-11-15 仍可读取，但属于繁体中文测试时期公告，**不是对用户所在地区现行完整协议或具体处罚阈值的核验**。它至少说明“不读取内存、不修改游戏数据”和“官方允许自动操作”不是同一判断。

安装版 `config.py:251–260` 的软件说明也明确警示使用软件可能导致账号被封。没有证据将本次处罚具体归因于 PostMessage、Pynput、10 毫秒点击、拖拽直线、Windows 副会话或某个依赖。不要通过反复触发、改输入伪装或试探时长寻找所谓安全阈值。

## 已核查的恢复风险

以下安装版路径均相对 `%LOCALAPPDATA%\ok-ww\data\apps\ok-ww\working`，是源码静态检查，不是本次弹窗的运行轨迹：

- `src/task/SkipDialogTask.py:26–32`：`skip_message()` 按 `message`、`message_dialog` 模板定位后点击，不读取弹窗正文。只有实际命中模板时才会进入该分支，尚未核实反作弊弹窗会否匹配。
- `src/task/BaseWWTask.py:744–797`：`wait_login()` 在未登录状态下可关闭 `login_close`、点击登录或进入游戏；其中部分关闭分支不检查正文。不能据此断言每次踢出都会重登，登录状态仍是前提。
- `ok/task/TaskExecutor.py:833–861`：一般异常可禁用当前任务并截图，但不是所有异常都触发全局停机。
- 本项目旧的 `tools/okww/dismiss_kick.py` 用包含“登录”的宽泛正则确认弹窗后点击右侧按钮。离线用例已复现：“反作弊检测异常”与“登录”同时出现时，也会继续关闭弹窗。

这些路径说明告警可能被普通恢复逻辑误处理，并不证明它们触发了第一次检测。未知弹窗不应当作可以自动恢复的普通故障。

## 当前工作区的保护

[历史暂停记录](../runs/services/okww/safety-stop-20261115.archived-20261116.json)保留原始用户报告、来源和截图尚未独立核验的说明。人工恢复不覆盖原事件，也不会让程序自动识别新的处罚或猜测处罚次数。出现新告警时，应重新建立 `runs/services/okww/safety-stop.json` 并停止任务。

[客户端](../tools/okww_mcp.py)在两个位置检查 `runs/services/okww/safety-stop.json`：建立连接前，以及准备调用 `run_task` 时。只要该路径存在，就拒绝派发新任务；内容为空、JSON 损坏、`active: false`、过期日期或同名目录都不能自动解除暂停。检查路径时出现权限等错误，也不会继续派发。

- 不会在 24 小时后自动恢复，没有自动删除标记或强制绕过参数。
- 保留截图、状态查询、停止任务和退出接口的既有客户端通道。保留通道不等于已执行停止，也不证明原生截图等工具没有设备初始化副作用。
- 旧的 [dismiss_kick 工具](../tools/okww/dismiss_kick.py)不再点击、等待登录或重连；其任务方法尝试保存截图和 OCR 文本后报错，要求人工核查。**不要为了采集证据而提交这个原生任务**：框架可能在进入任务方法前启动或登录游戏；暂停标记存在时，客户端会阻止该提交。

### 保护范围

这不是全局输入锁。它不能中止已提交任务，不能控制直接调用原生 MCP、原生 GUI、其他客户端或用户输入，也不能把“检查后、实际派发前”的并发竞态完全消除。原生自动登录、自动跳过任务和用户配置本轮未改动。出现告警时，应停止使用自动任务入口，而不是改走另一客户端。

2026-11-15 设置暂停时读取进程列表，未发现该安装版 Python 进程；当时没有启动或重启后端、连接原生 MCP、操作游戏或进行实机处罚测试。此前两份输入实现的 SHA-256 保持不变；这些是历史检查，不是本次人工恢复后的运行状态。

## 出现告警时如何处理

1. 停止自动任务，确认后端没有继续输入。若任务已在运行，客户端拒绝新提交不能替代对现有任务的停止确认。
2. 保留完整弹窗截图、错误码、准确发生时间、服务器区服和任务标识，以及相邻日志。分享材料前遮盖 UID 等个人信息；不要提供密码、令牌或验证码。
3. 不自动点击继续、不重复登录测试、不在限制结束后自动重跑。持续时间或踢出次数尚未核实，无法给出“运行多久不会封”的保证。
4. 通过游戏内官方客服核实处罚原因、自动化使用边界和可用的复核流程。若停止自动化后的正常手动操作仍出现同样提示，记录这一事实供官方进一步排查；本次未执行此类实机对照。
5. 暂停仅由人工完成事件核查后管理，没有自动恢复条件。移走标记会解除本客户端的限制，但不表示游戏官方允许恢复自动化；不要将移除文件当作处罚问题的修复。
