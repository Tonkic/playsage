# 检查 OKWW 输入失败与断联

本页记录 2026-11-15（本地时间 UTC+08:00）对本机安装版 OKWW 的第二轮输入可靠性修复及后续拖拽错误保留补丁。补丁保留第一轮[拖拽修复](okww-input-repair.md)，修复异常后的清理及错误传递。**只完成离线验证，未验证断联率或反作弊误判率下降，也没有进行游戏实测。**

## 先区分断联原因

“纯视觉”说明识别方式，不能据此确定服务端断联原因。输入补丁阶段核对 `runs/okww` 与 `docs` 的文本记录时，未找到完整处罚证据链；随后用户明确说明弹窗写有反作弊踢出，重复出现后曾有约 24 小时限制。现在按反作弊告警处理，不再将本次报告假设为普通网络故障；但尚未独立核验弹窗、错误码和处罚记录，不能确认具体触发项或是否属于误判。处置与新增客户端保护见[暂停自动任务与人工核查](okww-safety-stop.md)。未重新识读历史图片，未读取账户凭据或遍历安装版原始 MCP 日志。

已有[每日日志](../runs/okww/daily-complete/run.log)中的 `is not connected, please select the game window` 来自设备/窗口检查，相邻记录还标记 `connected: True`，不能直接解释为游戏服务器踢线。[历史实测](live-ww.md)另有加载超时和恢复记录，它们同样不是反作弊结论。恢复脚本的文件名或匹配关键词也不能替代实际弹窗证据。

再次出现异常时，先停止当前任务并确认输入已停止，保留弹窗截图、提示原文、发生时间、run_id 和前后日志。区分游戏网络断开、账号异地登录提示、Windows 应用无响应、设备窗口丢失，以及 MCP 客户端断开；不要因为客户端请求失败就再次派发同一游戏操作，也不要在未知状态下自动重连续跑。

本页后文的输入补丁范围和测试计数仍对应各自历史工作区快照；告警暂停补丁的最新结果及其非全局保护边界见[安全暂停说明](okww-safety-stop.md#离线验证)。

## 本轮修改

目标目录：`%LOCALAPPDATA%\ok-ww\data\apps\ok-ww\working`。第二轮仅修改以下五个方法体，保留签名、既有拖拽补丁及其他函数。后续拖拽补充的范围单独列在表后。

| 后端与方法 | 行为变化 |
| --- | --- |
| `PostMessageInteraction.post` | Windows 消息发送抛出异常后，记录日志并原样向调用方抛出；不再吞掉异常，不新增重试 |
| `PostMessageInteraction.send_key` | 校验短按时长；按下或等待中断时在 `finally` 中尝试松键 |
| `PostMessageInteraction.click` | 校验时长；按下和抬起固定在同一目标 HWND 与坐标；按下或等待中断时尝试抬起 |
| `PynputInteraction.send_key` | 校验时长和可输入状态；失焦明确报错；成对短按通过 `finally` 尝试释放 |
| `PynputInteraction.click` | 初始、按下前和持按等待结束时检查可输入状态；异常或失焦后尝试释放，不再回移光标；正常成功时保留 `move_back` |

`down_time` 继续以秒为单位。负数、NaN 和无穷值在发送输入前被拒绝。正常点击和短按时长未作随机化或额外减速，PostMessage 仍支持后台输入。没有引入 HumanCursor、验证码服务、新输入驱动或第二套后端。

四个点击/短按方法在操作与释放同时失败时保留最初异常，将释放错误通过 `add_note()` 附加；仅释放失败时直接抛出释放异常。释放只尝试一次，不自动重发输入。

后续补充只修改 `PostMessageInteraction.swipe` 和 `PynputInteraction.swipe`：使拖拽采用同样的异常优先级，避免释放错误覆盖原始输入错误、失焦提示或 `KeyboardInterrupt`。保留拖拽时长、采样、坐标、终点停留和正常输入时序；该补充改善错误诊断，不等于证实或修复服务端断联原因。

Windows 输入异常向调用方传播，不等于所有上层任务都会停止；上层仍可能捕获异常。补丁不是全局断联检测器或永久停止开关。`finally` 只保证清理调用被尝试，不能保证 Windows 或游戏接受该输入，也不能覆盖强制杀进程。

本轮没有改变独立 `mouse_down`/`mouse_up`、`send_key_down`/`send_key_up` 的跨调用持按管理，没有改活动策略、用户配置、操作频率或战斗策略。窗口焦点检查与实际输入之间仍存在竞态；这不是对任意并发输入的保证。

## 离线检查

只对已检查、可信的本地安装源码运行。测试提取指定方法的 AST，并以模拟时钟、Windows 消息和 Pynput 控制器执行，不导入完整 OKWW、不连接 MCP、不发送游戏输入；它不是不可信代码沙箱。

```powershell
$env:OKWW_WORKING_DIR = Join-Path $env:LOCALAPPDATA 'ok-ww\data\apps\ok-ww\working'
uv run pytest tests/test_okww_input_cleanup.py tests/test_okww_swipe.py -q
uv run pytest -q
uv run ruff check tests/test_okww_input_cleanup.py tests/test_okww_swipe.py
```

未配置 `OKWW_WORKING_DIR` 时安装版专用测试跳过，显式配置无效路径时失败。检查后可用 `Remove-Item Env:OKWW_WORKING_DIR` 清除当前终端设置。

- 第二轮最终检查为两轮输入测试合计 141 通过、11 跳过，项目完整测试 372 通过、11 跳过；这些是拖拽错误保留补充前的工作区快照结果。

## 生效、备份与回滚

第二轮及本次拖拽补充应用前均未发现该安装版 Python 进程。只修改磁盘文件，没有启动或重启 OKWW，也没有操作游戏。后续正常启动才会加载这些文件；安装器更新或重建 `working` 可能覆盖补丁。不要对未知版本自动重放补丁，先检查版本、源码及离线测试。

备份分为三层；各层均保留两个源文件和 SHA-256 清单，不能交叉覆盖：

| 层次 | 清单与备份内容 |
| --- | --- |
| 第一轮拖拽 | 见[第一轮说明](okww-input-repair.md#备份与回滚)；备份不含本页的后续修复 |
| 第二轮点击/短按 | [输入清理清单](../runs/services/okww/backups/input-cleanup-20261115-015621/manifest.json)；备份已含第一轮拖拽修复 |
| 后续拖拽错误保留 | [当前补丁清单](../runs/services/okww/backups/swipe-error-priority-20261115-021349/manifest.json)；备份已含前两轮完整修复 |

当前安装文件哈希以最后一层的 `after_sha256` 为准。此次同时核对了第二轮原始备份、第二轮修改范围，以及补充前后只改变两个 `swipe` 方法体；签名、其他方法和既有正常拖拽行为保持不变。

> **警告：** 回滚会恢复相应层的缺陷。先停止任务和后端并确认没有活动输入。必须从最后一层向前逐层回滚，不得直接使用旧整文件备份覆盖新补丁。

1. 选择最后一层清单，核对目标路径及两个当前文件的 SHA-256，必须分别等于该层的 `after_sha256`。
2. 核对两个备份的 SHA-256 等于该层的 `before_sha256`。任一文件已被升级或再次修改时停止，不覆盖后续内容。
3. 全部匹配后，将两个备份复制回各自目标，再核对目标 SHA-256 等于该层的 `before_sha256`。
4. 如需继续回滚，依次处理第二轮、第一轮，并对每一层重新执行全部路径与哈希检查。

本次检查范围是本地工作区快照和清单指向的安装文件。已同步本页及第一轮说明中的后续补丁入口、验证结果和分层回滚；README 已有两页入口及离线限制，无需增加新入口。没有架构或依赖变动，历史实测结果保持原样。修复降低的是已复现的输入错误风险，不能据此宣称已消除断联或反作弊误判。
