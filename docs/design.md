# PlaySage 架构与执行边界

PlaySage 是一个基于 MCP 和 Agent Skills 的多游戏活动学习平台。它让 Agent 查找活动知识、回看操作证据、保存工作记忆，并检查明确规则下的状态变化。游戏截图、原生识别和实际输入由独立后端提供。

当前交付为 **0.1.0 开发原型**。本页说明已经实现的结构，以及尚未开放的执行能力。原始设计来源为用户提供的《QuestWeaver（织境）v0.3 — 四游戏活动 Agent 开发方案》；方案版本不等于软件已实现的版本。

发行包、主命令及内部实现均使用 `playsage`。实际模块位于 `src/playsage`，`src/questweaver` 只把旧命令及导入转发至同一模块对象。桌面分身项目与进程名为 `PlaySage.ChildSession`，会话变量为 `PLAYSAGE_CHILD_SESSION_ID`。数据路径、锁键和活动包不因改名迁移。详见[改名与兼容说明](rename-playsage.md)。

> **重要：** 通用执行流程仍只运行内置模拟策略。OneDragon 实机工具是独立开发入口，尚未接入通用活动包重放。历史证据、工作记忆和离线回测都不能授予真实输入权限。

## 架构概览

系统把分析与执行分开。Agent 负责理解目标和选择策略；PlaySage 维护知识、证据与约束；外部后端提供截图、识别和输入能力。

```text
用户目标
   |
   v
Agent（Codex）：理解活动、查看画面、提出下一步
   |
   +--> 活动知识：game_packs + event_packs
   |       |
   |       +--> registry：索引、兼容性、生命周期、运行摘要
   |
   +--> 离线分析入口：offline_cli
   |       +--> evidence：保存和回看原始证据
   |       +--> memory：维护带证据引用的活动工作记忆
   |       +--> rule_validation + grid_route：比较预测与人工标注
   |       （这三个入口不连接游戏后端）
   |
   +--> 通用受控执行：GameContext --> MockAdapter
   |       （只运行内置模拟策略，不导入活动包 Python）
   |
   +--> 独立开发工具：onedragon_step / repair_grid
           --> 窗口与会话检查 --> 原生 MCP --> 游戏
           --> 操作后观察 --> 证据记录与独立结果复核
```

MCP、原生后端和 Maa 是执行接入方式，不是必须串联的处理流水线。MaaMCP 仍是后续可选执行器，当前未执行其 Pipeline。项目不实现新的 OCR、底层输入框架、Pipeline 解释器、Gateway 或 GUI。

## 组件职责

每个组件只负责一类信息，避免把“记住了”“预测正确”和“允许执行”混为一谈。

| 组件 | 当前职责 | 不负责的事项 |
| --- | --- | --- |
| Agent 与 Agent Skills | 阅读活动知识、理解画面、规划探索步骤、整理活动包 | 不因历史成功记录而跳过实时检查 |
| `models.py` | 校验活动包契约、入口、路径和文件摘要 | 不把自定义 manifest 当作后端原生格式 |
| `registry.py` | SQLite 索引、搜索、兼容性、生命周期和运行摘要 | 不维护细粒度活动工作笔记；不授予 `verified` |
| `evidence.py` | 原图归档、帧与步骤关联、历史检索、裁剪、像素和差异 | 不从像素变化推断目标达成 |
| `memory.py` | 活动工作记忆、证据引用、版本隔离和修订冲突检测 | 不自动跨活动合并知识，不授权重放 |
| `grid_route.py` | 网格求解和单步纯状态转移 | 不从任意截图自动生成棋盘 |
| `rule_validation.py` | 比较规则预测与带来源的观测标注 | 不进行独立视觉验真，不自动修正规则 |
| `runtime.py` | 受控模拟执行、窗口锁、动作预算、停止和最终验证 | 不动态运行活动包 Python |
| 独立后端与开发工具 | 原生截图、识别及受保护的单步实机试验 | 尚未形成通用真实活动重放服务 |

## 数据布局与权威记录

活动定义、运行证据和可变工作记忆分别存放。修改工作笔记不应改变活动包摘要。

| 路径 | 保存内容 | 权威性与用途 |
| --- | --- | --- |
| `game_packs/<game>/knowledge.md` | 游戏知识、上游来源、接入状态 | Agent 阅读的游戏级背景 |
| `event_packs/<game>/<slug>/` | `event.yaml`、`SKILL.md`、规则、入口和资源 | 活动包定义；所有包内文件参与 SHA-256 |
| `data/events.sqlite` | 活动索引、状态和运行摘要 | registry 数据，不是工作记忆正文 |
| `runs/traces/<uuid>/trace.jsonl` | 模拟执行中的观察、动作和判定 | 通用运行日志 |
| `runs/observations/<uuid>/` | SRA 原图和观察记录 | 原始只读采集来源 |
| `runs/onedragon/` | OneDragon 原图、观察和动作记录 | 实机开发工具的原始来源 |
| `runs/evidence/<run_id>/` | 统一帧、步骤、原图副本和派生图 | 可追溯的分析证据 |
| `data/event_memory/<game>/<slug>/<package_digest>/memory.json` | 条目、证据引用、修订号和历史 | 活动工作记忆的唯一权威记录 |
| 同一记忆目录下的 `GUIDE.md`、`WORKING.md` | 知识与工作进度的可读快照 | 仅导出视图；编辑它们不会更新 JSON |
| `runs/reports/grid-<uuid>.json` | 显式导出的网格回测结果 | 离线报告，不是执行授权 |

活动包内任意文件变化都会改变摘要，并使已有索引失效为 `stale`。运行产物放在包外，不参与包摘要。索引事务先校验全部包；重复 ID 或无效入口会使整批索引不写入。

### HSR 遗器离线分析

`playsage.hsr_relics` 是崩铁游戏级知识和离线分析能力。它复用 RelicForge 的 Reliquary 导入模型、角色构筑评分、套装/主词条门槛和强化预期评分，数据与配置分别放在 `data/hsr/relic_database/` 和 `game_packs/hsr/relic_scoring/`。数据库 `manifest.json` 记录 pinned 上游版本与文件摘要；本地策略通过 overrides 文件覆盖生成配置。

该模块不属于活动包执行入口，也不调用 OCR、MCP 输入或 Windows 游戏控制。评分结果只能支持人工分析；游戏观察、身份确认和任何遗器强化、锁定、弃置动作仍需独立后端和后续安全审核。

## 分析数据流

一次分析循环可以使用以下步骤。它不是自动执行流水线；Agent 或用户需要显式提供来源、标注和判断。

1. **取得观察。** 使用已有 SRA 或 OneDragon 观察文件。离线命令本身不启动截图服务。
2. **保存证据。** 导入原始图像字节，记录来源、上下文、UTC 时间、运行内序号和 SHA-256。
3. **查看画面。** 通过历史、原图、裁剪、像素或差异找到相关信息。`inspect` 返回路径后，调用方仍需实际打开图像。
4. **记录判断。** 将活动知识、进度、失败或假设写入工作记忆，并附证据引用。
5. **检查规则。** 对已明确的网格棋盘提供动作和前后状态标注，再比较预测与标注。
6. **决定下一步。** 规则矛盾时复核标注或规则；证据不足时重新观察。任何真实操作都必须通过单独的实时保护。

证据记录使用 UTC 时间和序号检索。进程内的 monotonic 时间只用于实时控制，不作为跨进程历史时钟。裁剪和差异图是派生产物，不能替代原图。

## 活动记忆的适用性

工作记忆按活动 ID 和包摘要隔离，并检查游戏版本和分辨率。默认兼容条件来自活动包声明，不代表已探测到实际游戏版本。

| 条目状态 | 含义 |
| --- | --- |
| `hypothesis` | 尚待确认的假设；允许没有证据引用 |
| `observed` | 记录人判断已经观察到的事实；必须附证据 |
| `supported` | 记录人判断得到支持的结论；必须附证据 |
| `refuted` | 记录人判断受到反驳的结论；必须附反驳证据 |

这些状态由记录人显式选择。程序校验证据是否存在、图像哈希及上下文是否一致，不替代人的视觉判断。未知游戏版本不能支持已确认条目。

读取或导出时，程序重新核对包摘要、兼容条件和证据。变化或证据失效会使结果显示 `needs_review`；`context_matches` 仅表示所检查的上下文相符。长期持有的实例不能继续把旧包记忆标为适用，写入前也必须检查包是否变化。

更新使用协作式 OS 锁、修订号比较和同目录原子替换。旧条目保留在历史中，原证据继续受到清理预览保护。不同活动或版本不会自动合并。

## 网格规则验证

首个离线模型是现有网格规则，不是通用世界模型。棋盘由人工或已有识别结果明确提供；程序不新增 OCR，也不猜测未标注的画面状态。

`grid_route.advance` 预测一次按键及其触发的自动移动。规则包括简单路径、全部或顺序收集、通道端口、全局顺时针旋转、快速通道和同色传送。原有 `solve` 与 `actions_for` 接口保持不变，求解仍有节点预算。

| 结果 | 含义 | 下一步 |
| --- | --- | --- |
| `match` | 当前规则预测与输入标注一致 | 保留报告；真实操作前仍需观察 |
| `mismatch` | 预测与标注存在字段差异 | 复核标注、规则或采集时机 |
| `insufficient_evidence` | 缺图、缺标注、重复来源、未知规则或上下文不符 | 补充独立证据或暂不使用模型 |

同一原始观察重复导入，或同一多图观察内的两张图片，不构成独立的前后观察。独立采集的图片即使像素相同仍可用于检查。

报告保留模型标签、棋盘摘要，以及求解器和验证器源码哈希。`success` 只表示本次离线检查是否全部匹配；报告始终返回 `replay_allowed=false` 和 `goal_status=not_evaluated`。代码或规则变更后需要重新回测。

## 活动包生命周期

生命周期与记忆条目状态是两套不同概念。支持某条结论，不会把活动包提升为可重放状态。

| 包状态 | 含义 | 当前处理方式 |
| --- | --- | --- |
| `draft` | 策略尚未完成 | 新建活动包的初始状态 |
| `candidate` | 存在候选流程，实机验证尚不完整 | 可索引和分析，不授权无人值守执行 |
| `verified` | 设计中用于已完成证据审核的包 | 尚无晋升入口；YAML 中的声明按 `candidate` 索引 |
| `stale` | 包变化或被主动标记失效 | 保留失效状态，重新索引不会清除 |

兼容性目前只检查精确游戏版本和分辨率，不推断版本范围。模拟结果标记为 `simulation`。未来若开放晋升，必须绑定包摘要、兼容性、后端能力和重新进入关卡后的实机成功证据。

## 执行路径与安全边界

当前存在两条执行路径。通用模拟执行与独立实机开发工具不能互相替代。

### 通用受控执行

`GameContext` 提供 `observe`、`detect`、`act` 和 `verify`。`run_skill` 保留接口，但明确拒绝分发；活动包 Python 不会被动态导入。

- 只对 `MockAdapter` 运行受控的内置策略。
- 每次动作引用最新观察 ID，并检查时间、窗口、尺寸和场景；操作后刷新观察。
- 使用跨进程窗口锁、动作预算和异步超时。
- 超时后停止适配器；停止另有 5 秒预算。无法确认停止时记录 `stop_failed`，运行按失败处理。
- 最终验证独立检查目标，不信任策略自报成功。

异步超时不是任意 Python 代码的沙箱。`max_retries` 目前只是未来恢复逻辑的上限元数据，不会触发自动输入重试。真实适配器仍需补齐目标重新定位、按键释放、停止失败后的隔离和人工接管。

### 独立 OneDragon 开发工具

`tools/onedragon_step.py` 和 `tools/repair_grid.py` 通过原生 MCP 进行实机开发试验，尚未成为通用适配器。

输入前检查后端进程与会话、窗口标题与几何、前台状态、原生任务占用和最新观察。截图路径必须位于指定克隆的 capture 目录，解码后必须为 1920 × 1080。点击还检查目标区域变化；动画控件可使用唯一、附近且未移动的原生 OCR 标签。

每次操作使用 0.12 秒短按。客户端取消后最多等待 5 秒确认原生返回，未知结果禁止自动重试。场景比较只覆盖原生精确识别结果，不能代替 Agent 对未知页面的观察。

统一动作记录区分以下状态：

| 状态 | 能够说明的事实 |
| --- | --- |
| `intent_recorded` | 意图已持久化；若进程中断，不能据此判断输入是否发送 |
| `not_dispatched` | 在本次调用派发前被取消或被检查拒绝 |
| `backend_returned` | 后端已返回，不代表游戏目标完成 |
| `observed` | 后置观察已归档，不代表游戏目标完成 |
| `incomplete` | 输入可能已经发生，但记录链路或后续操作未完成 |

意图落盘后，工具再次检查取消、绝对时间预算和原始实时观察时效。后置故障明确报告“输入可能已发生”，不会补发输入。存储故障可能使文件停留在旧状态；必须停止并重新观察。

`repair_grid.py` 在每步后复核原生 OCR 关卡与计数、当前位置高亮和未触碰格子。工具结束标记为 `needs_visual_review`，最终结果仍由 Agent 独立查看。

> **警告：** OS 锁只能约束遵守同一锁协议的调用方，无法阻止用户或独立 MCP 同时输入。客户端取消也不能证明服务端动作已取消。

### SRA 只读连接

SRA 通过官方 MCP SDK 的 Streamable HTTP 客户端先读取 `tools/list`，再调用实际存在的 `sra_screenshot`。只接受可解码的内联 PNG/JPEG，并保留原始字节。

当前不调用 SRA 按键工具，不推断 OCR 返回结构，不自动启动游戏，也不修改用户的全局 Codex 配置。窗口身份和视觉模型接收仍需另行核验。

## 验证状态与后续工作

历史实测记录显示，OneDragon 已完成绝区零活动前四案 16 关及奖励领取，其中第二至第四案使用隐藏的独立 Windows 会话。这些历史结果不等于升级后或新增记录链路的重新实机验收。

第一案候选策略已保存，但重新进入只显示“已完成”，尚未取得完整重放证据。新增证据、记忆和规则验证功能目前只完成离线验收。

后续工作按以下依赖顺序推进：

1. 核验实际后端的窗口身份、分辨率、坐标、OCR、停止和按键释放行为，并补充契约测试。
2. 将通过验证的独立工具接入通用适配器，同时补齐真实输入所有权和停止失败隔离。
3. 在可重复进入的关卡取得重放证据。
4. 实现证据绑定的 `verified` 晋升与真实重放分发，再扩展其他执行器。

这些工作不属于当前离线命令的能力，也不会在文档示例中自动执行。

## 文档编写约定

项目采用[文档编写规范](documentation-standard.md)，遵循 Microsoft Writing Style Guide 的任务导向、主动表达和事实约束。每轮修改都检查文档影响；确无影响时，在本轮交付说明记录检查范围、原因和实际验证，不强行为用户指南增加流水账。

### 文档同步工作流

GitHub Agentic Workflow 是独立的开发维护路径，不参与游戏执行。源文件为 `.github/workflows/docs-sync.md`，由固定版本的官方编译器生成 `.lock.yml`。当前只完成本地准备；是否部署及启用需另行确认。

```text
分支 push → 固定 before/after 提交范围 → 新文档 Agent 静态分析
    ├─ 无影响：带理由的报告，不创建空 PR
    ├─ 缺少必要证据：受阻报告，不猜测
    └─ 有影响：白名单内最小修改 → 后置检查 → safe output 草稿 PR → 人工审阅
```

- 同一分支按队列串行处理，不把一次 push 等同于一次本地 commit。Agent 分支不再触发生成；人工文档修改仍接受检查。
- 新分支按整棵当前树检查；普通或强推使用明确的前后提交。缺少基准对象时停止，不用父提交替代。
- Agent 的 GitHub 权限为只读。发布由独立 safe-output job 执行，并以逐文件白名单限制实际补丁；工作流、检查程序和写作规范不在白名单内。
- 后置检查程序从触发提交读取，以 Python 隔离模式运行，检查工作区改动、报告、文件类型和本地链接。发布前再次核对源分支 SHA；报告不能验收更新后的提交。
- 不自动合并或直接推送目标分支，不修改历史报告、活动包、运行数据或安全配置。文档内容是否准确仍需人工对照具体 PR diff，静态检查不替代语义审阅。
- 工作流不执行项目测试或游戏代码，也不采集 CI 测试结果；报告必须标明项目测试和实机未验证。未来如接入测试证据，必须绑定完整 SHA，并单独审阅权限及检查逻辑。

部署条件、生成文件和验证方法见[准备文档同步工作流](documentation-workflow.md)。
